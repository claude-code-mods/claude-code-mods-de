> Dieses Plugin is experimental und does have some [known limitations](#caveats)

## Installation

Install terminal-browser
```
curl -fsSL https://terminal-browser.sh/install | bash # or brew install terminal-browser
```

Ensure you are on the latest version of claude code
```
claude update
```

Enable claude code UI plugins by adding this to `~/.claude/settings.json`:
```json
{
  "env": { "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1" }
}
```




Install the terminal-browser plugin
```
# set the marketplace
claude plugin marketplace add zenbu-labs/terminal-browser

# install the plugin
claude plugin install terminal-browser@terminal-browser
```

Now du kannst ausführen "/Browser" inside claude code to öffnen the Browser

### Updating

Update the claude code plugin
```
claude plugin update terminal-browser@terminal-browser
```

Update terminal-browser
```
terminal-browser upgrade
```

### Configuration

Du kannst configure the terminal-browser plugin to include a Werkzeug that claude can verwenden to öffnen the Browser. Das ist standardmäßig off, since claude can already verwenden the `terminal-browser` CLI to öffnen the Browser inside the terminal through a split pane. Du kannst aktivieren the Werkzeug by adding the following to your ` ~/.claude/settings.json`:

```json
{
  "pluginConfigs": {
    "terminal-browser@terminal-browser": {
      "options": {
        "agentTool": true
      }
    }
  }
}
```


## terminal-browser plugin API

The terminal-browser plugin comes mit an API du kannst verwenden within another claude code plugin to programatically öffnen the Browser und load a URL. Some examples of useful plugins du kannst build mit this are:
- `/tldraw` slash Befehl that öffnet tldraw in the claude code split pane
- `/open-pr` slash Befehl that öffnet the PR associated mit the Branch you are working on

```typescript
export type BrowserOpenInput = { url?: string }

export type BrowserOpenResult =
  | { ok: true; url: string }
  | { ok: false; error: string }

export type Browser = {
  open: (input: BrowserOpenInput) => Promise<BrowserOpenResult>
  close: (input?: Record<string, never>) => Promise<boolean>
}

// usage: in your plugin's hooks module
on('command.run', { command: 'tldraw' }, async ($) => {
  const result = await $.browser.open({ url: 'https://www.tldraw.com/' })
  return { text: result.ok ? 'Opened tldraw' : result.error }
})
```

## How does it work?

terminal-browser verwendet the [kitty graphics protocol] to display pixels generated by a real Browser inside the terminal. To display the Browser inside claude code, we verwenden claude codes neu [function hooks API](https://github.com/anthropics/claude-code/issues/91870).

terminal-browser's internals have been extracted to a javascript library - https://github.com/zenbu-labs/terminal-browser/tree/main/pixel - wenn du would like to build your own graphical application inside claude code/the terminal


## Supported terminals

The terminal-browser claude code plugin will nur work in terminals that support the [kitty graphics protocol], und implement [kitty unicode placeholders](https://sw.kovidgoyal.net/kitty/graphics-protocol/#unicode-placeholders). The most popular terminals that support this feature are:
- [ghostty](https://ghostty.org)
- [kitty](https://sw.kovidgoyal.net/kitty/)

If your terminal does nicht support the required features, trying to öffnen the Browser inside claude code may garble the TUI

In addition any terminals that are built on libghostty will support this feature, some examples are:
- [cmux](https://cmux.com/)
- [supacode](https://supacode.sh/)

Du kannst find mehr libghostty based terminals here: [awesome-libghostty](https://github.com/Uzaaft/awesome-libghostty)

Even if your terminal supports the required graphics feature, wenn du are läuft a multiplexer, das Plugin may nicht work. Das ist because multiplexers rewrite the Ausgabe of terminal programs und breaks terminal graphics commands. tmux support will be arriving soon (terminal-browser derzeit works in tmux, just nicht through the claude code plugin yet), und within herdr performance is very bad when läuft through the claude code plugin, aber will likely improve soon. Other multiplexers I have nicht tested, so if it does nicht work please Datei an Issue und I will see if we can support this.




## Caveats:
- depends on your terminal supporting the [kitty graphics protocol]
- the mouse position will sometimes be slightly off, since claude code does nicht aktivieren pixel coordinate mouse reporting
- das Plugin needs to make fetch requests to a local http Server to communicate mit the terminal-browser CLI, which may cause a Prompt to zeigen in your OS that your terminal wants to access the local network
- claude code sets a very high min width for the chat area, so its sometimes nicht possible to resize the Browser to the size you want
- das Plugin depends on the experimental function Hooks claude code API, which is unstable, so das Plugin may break between releases

[kitty graphics protocol]: https://sw.kovidgoyal.net/kitty/graphics-protocol/
